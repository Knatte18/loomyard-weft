# Gate mutation report step, with its survivors fed to Code-Review

The mutation trial (`docs/research/speed/mutation-trial-2026-11-19/report.md`) recommended building the `mutation` gate report step once three bound changes were made.
This change makes those three changes and adds the step, the template keys that run it and a Code-Review rubric marker that reads its survivors.

## What changes

- **Line mutants skip noise sites (`internal/testcover`).**
  `PlanLineMutants` places no mutant inside a statement that only logs.
  That is a call into `internal/logger`,
  or an `if` with no init statement and no call in its condition whose every branch only logs, its condition included.
  It also places none inside a `==` or `!=` comparison of `runtime.GOOS` with the name of a platform other than the build context's.
  A comparison naming this platform keeps its mutant.
  `PlanMutants` marks the sites, and only the line planner drops them, so `lym gate redundant` is unchanged.
  The old rule, which skipped only a dropped logger call, is now covered by the log-only rule.
- **The cap spreads over the changed functions (`internal/gatecli/mutatecheck.go`).**
  `mutation_max_mutants` still takes one mutant per changed function per round.
  A round that has more functions than the cap leaves now takes functions spread evenly over the order of package, file and name.
  Before, it took the first ones in that order.
  The cap's mutants are spread evenly over the changed functions in the order of package, file and name,
  so the later packages and files are sampled too.
- **The `mutation` report step (`internal/gatecli/mutation.go`, `mutationreport.go`).**
  A gate key whose `reports` lists `mutation` runs it after the reach and redundancy steps, under the same memory guard.
  It never changes the call's exit code.
  It diffs from the reach step's base and runs the refresh and mutation check that `lym gate mutate` runs.
  Those now live in one `mutationCall` that both use.
  It writes `mutation.json` to the worktree's gate directory.
  The file holds the counts, every survivor with its possible killers, every unjudged mutant, uncovered changed block and package not judged, and the refresh's errors.
  It also records the changed functions with their hashes and the Go file hashes of their packages, so `MutationReportMatches` can match it against a commit.
  That match logic is shared with `ReachReportMatches` through `changedFunctionsMatch`.
  The step prints one stderr line, for example:
  `gate test: mutation report: 1 mutants run, 1 killed, 0 survived, 0 unjudged, 0 uncovered changed blocks, 0 packages not judged; written to …/mutation.json`.
  A red gate, a call outside a hub, a non-Go scoper or a worktree with no parent branch gets a report that judges nothing, and its line prints the note.
- **Config (`internal/gateslot`).**
  `ReportMutation` is accepted in a key's `reports`.
  The template lists `mutation` last on every key of scope `diff`: `webster-fix`, `darn-write`, `code-burler-fix` and `pr-review`.
  The comments of the template's bound keys now name the step.
  `Config.HasGoCoverageMaps` reads a scoper table, so the steps that read Go coverage maps name no language literal.
- **Code-Review rubric.**
  `loom-rubric-code-review.md` gains a `## Mutation report` section with a `mutation_report` marker.
  `loomcli` fills it through `mutationReportNote` with the counts and one line per survivor, but only when the report matches HEAD's tree.
  Otherwise it fills one line saying why no current report exists.
  The marker is threaded through `shedrecipe.Env`, `shedadapters.RubricNotes` and `BouncerConfig`, the same way as `reach_report`.
  The rubric says to read a survivor as a candidate for a missing check, never a finding by itself.
  It names the kinds of survivor no test can reasonably kill.
- The result types of the mutation check are exported (`MutationCounts`, `MutationSurvivor` and the rest), so the report and the review note can carry them.
  The JSON field names of `lym gate mutate`'s envelope are unchanged.
- Docs: the package docs of `gatecli`, `gateslot`, `testcover`, `loomcli`, `shedadapters` and `shedrecipe`;
  `PATTERN-test-speed` and `PATTERN-coverage-map-reader`; and `docs/overview.md`.

## Design decisions

- "The template's `diff` keys" is read as every key of scope `diff`, so `webster-fix` and `pr-review` also run the step.
  Only Code-Review reads the marker today.
- The summary line carries the six counts the record names.
  It adds `, N errors` only when the report holds error lines, so a step whose builds failed does not print all zeros silently.
- The review note carries the counts and the survivors only.
  The unjudged mutants, uncovered blocks and packages not judged stay in `mutation.json`, as the trial advised.
- A survivor in the note names its possible killers, the tests of other packages that the maps show reach its function.
  Those tests are not run.
- The other-platform skip covers only the comparison itself.
  The body of an other-platform branch is uncovered on this platform, so it gets no mutant in any case.
- The step keeps no earlier report for an unchanged tree, unlike the redundancy step.
  Each listing call runs the check again within `mutation_budget_min`.

## Tests

- `TestPlanLineMutants` gains rows for an `if` that only logs beside one that also returns.
  It also gains rows for a `GOOS` comparison with another platform beside one with this platform.
  The every-line row covers the new fixture functions.
- `TestDiffMutation_SelectWithinCap` pins the even spread under caps below and above the function count.
- `TestMutationReport_SummaryLine` and `TestMutationReport_ReviewLines` pin the stderr line and the review lines, including the line cap.
- `TestGateMutate` gains a row running `lym gate test --gate darn-write` with `reports: [mutation]` in a task pair.
  It checks the written report, the single summary line and that the report matches HEAD until a commit changes Clamp.
  Further rows pin the written survivors and uncovered blocks, the red tier call, and the red-gate, no-hub, non-Go-scoper and no-parent reports.
- `TestMutationStep_RecordFindings` pins that a failed call records no function or file hash, so its report never matches.
- `TestMutationReportMatches_RefusesAReportThatJudgedNothing` and `TestConfig_HasGoCoverageMaps` pin the match refusal and the scoper table.
- `TestPlanLineMutants` also pins the else, else-if, init-statement, literal-first and shadowed-`runtime` noise rules.
- `TestRenderMutationReportNote`, the wiring test, the rubric marker allowlist test and the Bouncer and Burler rubric tests cover the marker.
- `TestLoadConfig` now loads a key listing every report, and its template defaults carry the new lists.

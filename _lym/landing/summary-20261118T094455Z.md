# Drift: decision adds pass the judge check; the expect agent names keyed values by keys

This change fixes two drift bugs, issues #145 and #141.

## A parent decision during Drift-Verify no longer halts the judge

A parent can run `lym loom decision add` while a Drift-Verify judge session is running.
The verb commits `_lym/discussion/decision-record.md` on the records side.
When the judge finished, `JudgeSnapshot.Changes` counted that commit as the judge's edit,
and the run halted with `records: ... decision-record.md was changed`.

`TakeJudgeSnapshot` now also stores a copy of the decision record, named by the new `Deps.DecisionRecord`, beside the snapshot record.
`Changes` exempts the record when all of these hold:

- The records checkout lists the record as neither changed nor untracked, so the verb's commit has landed.
- The record differs from that copy only by `Added after Discussion` entries.
- Every entry and every carry-over block the copy held is still there unchanged.

The comparison uses `discussionparser.IdentityText`, `CheckAddedEntriesSubset` and the new `CheckCarryOversNotLost`,
so the check reuses the record format's own parser.
An edit anywhere else in the record, a dropped or rewritten entry, an edited or dropped carry-over block
and an uncommitted append are still reported as changes.
`loomcli`'s `driftDeps` sets the field from the run's decision record path.

Two forms of the verb write outside this exemption:
`--amends-plan` also commits `_lym/loom/amendment.yaml`, and a PATTERN-change form changes a bullet in the record's PATTERN section.
The verb now refuses both while the scope record's judge session is open.
Its refusal says to re-run the call after Drift-Verify has ended the session.
`driftJudgeSessionOpen` in `loomcli` reads the scope record's `judge_session` mark for that.

Design decisions:

- The issue allowed two fixes: refuse `decision add` while a judge runs, or exclude its commits from the check.
  This change takes the second for plain entries, so the parent never has to wait for a judge to record a call.
  The two forms above take the first, since their writes cannot be told from a judge's edit by content.
- The exemption is decided by content and checkout state, not by commit, matching how the snapshot already judges paths.
  `decision add` commits carry no trailer that marks them as lym's own commits.
- Bound: a committed `Added after Discussion` entry or carry-over block that the judge session adds itself also goes unseen.
  An uncommitted append, an edit or removal of an existing entry or block, and a `lym loom decision replace` are still reported.
  The package doc states the bound.

## The expect agent names keyed values by keys entries

When `key_patterns` keys every line of a case, each changed value is a keyed cell with line position 0.
A `lines` range counts positions among unkeyed lines only, so a range such as `"1-"` or `"7-433"` over such values never matched.
The drift gate then failed on every changed value.

The expect agent's format text now says that a keyed line is named only by a `keys` entry.
It also says that a range counts the listing's `line` positions, never file line numbers.
`ParseExpectation` is unchanged:
a range over a case whose baseline lines are all keyed stays valid, since the change can add unkeyed lines to such a case and only a range can name them.

Design decision: the issue allowed giving cells real file line numbers instead.
This change keeps a range's meaning as positions among unkeyed lines, which unkeyed identity pairing and existing expectations depend on.

## Tests

- `TestJudgeSnapshot` gains rows for a committed added entry, an edit beside an added entry, a dropped entry,
  an uncommitted added entry, an added entry beside a kept carry-over block and an edited carry-over block.
  It also gains rows for the fail-closed boundaries: an unset `Deps.DecisionRecord`, a record absent at the snapshot,
  and a new snapshot that clears an earlier copy.
- `TestCheckCarryOversNotLost` covers the new parser check.
- `TestDecisionVerb_Refusals` and `TestDecisionVerb_AmendsPlan` gain rows for the refusal while a judge session is open.
- `TestDriftDeps_CarryTheDecisionRecord` pins that `driftDeps` passes the run's decision record path on.
- `TestParseExpectation` gains an accepted row for a range over a case whose baseline lines are all keyed.

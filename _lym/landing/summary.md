# Research: what gets revised in raddle splits

Adds `docs/research/raddle/raddle-split-quality.md`, a study of every raddle run up to 2026-11-27 with proposed stencil changes.
No stencil or code changes.

## What the report finds

- 38 runs, 37 of them filed.
  Against their first stored proposal, 21 filed splits kept parts, recipes, profiles and dependencies,
  12 changed only dependencies and 4 changed parts, recipe or profile.
- The most common revision is a missing dependency on work already running or released.
- Revisions of part count and recipe are about size and cost.
  The stencil has no size rule and no condition for the `solid` profile,
  and its sentence on a tapestry's fixed cost favours larger parts.
- No revision was about parts overlapping a package.

The report holds the table of runs, the classes with counts and quoted requests,
and new stencil text for each class that needs one, with matching bullets for the split perch's rubric.

## Design decisions

- Revisions are counted as runs per class and author, split into the operator's own words, the orch's review and the split perch.
  Counting the operator's pane messages alone would leave almost nothing:
  they changed a proposal in one run.
- Words said in the orch chat count as the operator's, since many revisions were asked for there.
- One class of change, choosing which level the filed entries land under, needs a code and spec change;
  the stencil text proposed for it only makes the level visible.

## Limits

- One run's session is on another machine, and one proposal the operator described has no stored record.
- The size limits in the proposed stencil text are a judgment from the observed cuts, not a measurement.
- Classifying the revisions is a judgment.

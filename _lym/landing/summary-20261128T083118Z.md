# Show each tier's slot wait apart from its wall time in the gate summary line

A `lym gate test` call's own duration includes the wait for gate slots,
which under contention can dominate it (300 s was seen in one run).
Before this change the call's output showed only the run's wall time per tier,
so a caller who wanted the wait or the run time without it had to read the run records under the gate directory.

## What changes

- `gateslot.TierSummaryLine`, the stderr line printed after each tier, now carries `wait <s>s` after the scope form:
  `gate test: tier1 diff wait 300.0s discovered 3 passed 2 failed 1 skipped 0 wall 12.5s exit 1 log ...`.
  `wait` is the time from the start of the slot wait until the slots are held; `wall` is the run's own time, as before.
  A carried tier shows `wait 0.0s`.
  A rerun's line shows the slot wait the call spent, while its record holds none, so the report counts it once.
- The run record gains `slots_held`, the time the wait ended.
- `RunRecord.SlotWaitSeconds` computes the wait from the record.
  `lym gate report` uses it for its `wait_seconds` and `abandoned_wait_seconds` totals,
  which therefore no longer count the shared build or the `--copies` prebuild as wait.
- The `lym gate test` help and the `gatecli` package doc say that `wait` and `wall` appear separately on each summary line
  and that `wall` is the run time without the wait.

## Design decisions

- The wait goes on the per-tier summary line rather than in a new stdout field.
  A successful call prints no JSON envelope of its own, and the slot wait is per tier, since each tier takes its own slots.
- The build step's summary line is unchanged.
  The build's time is on the build line and not in the tier's wait.
  The `lym` prebuild of a `--copies` run is in neither `wait` nor `wall`; a run without copies counts it in `wall`.
- The wait stands before `discovered`, where the line's readers accept any text, and the reader patterns are unchanged.
  Verify logs are written by the `lym` on PATH, which need not be the reading binary,
  so a reader on either side of this change reads a line from the other.

## Tests

`TestTierSummaryLine` in `internal/gateslot/runlog_test.go` pins the exact rendered line.
`TestSummaryLineShowsTheSlotWaitAlone` in `internal/gatecli/slotwait_test.go` pins the wait printed and recorded
for a slotted run, a carried tier, a shared-build tier, a rerun and a `--copies` run.

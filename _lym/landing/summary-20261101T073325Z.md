# Dobby calls a driver dead only once the child had time to start one

Dobby's dead-driver notice fired for a go-driven run that had just started.
`lym loom start` writes the child's status as running before it spawns the detached `lym loom drive`, which takes the driver lock only as it starts.
A dobby probe tick inside that gap read the child as running with no driver strand and no lock, and posted `driver strand is dead` for a healthy run.

## What changes

- `internal/dobbyengine/runnotice.go`: a dead driver is a condition only once the child has been running for `driverStartGrace`, one minute, of awake time from its running episode's since.
  Machine sleeps and paused intervals do not count toward the grace, the same way they are left out of the idle clocks.
  Inside the grace a dead reading gives no finding at all, so no agent-based notice goes either.
- `internal/battencli/dobbynotice.go`: `childDriverLockHeld` also counts a held loom bootstrap lock (`loomengine.LoomBootstrapLock`) as a live driver.
  A loom bootstrap holds that lock from before it spawns the driver until the driver holds its own lock.
- `internal/dobbyengine/doc.go` and the `DriverAlive` seam's doc state both rules.

## Design decisions

- Both fixes, not one.
  The bootstrap lock alone leaves a gap: `lym loom start` seeds the status and commits it into the fabric before it takes the bootstrap lock.
  The grace alone covers that gap but not a bootstrap that runs past a minute, or a restart on a child whose running episode is old.
- The grace counts from the running episode's since, so it applies whenever dobby sees the child enter running, such as a resume after a halt, and not only at history 0.
  A halt and resume that falls between two probe ticks keeps the old since and gets no grace.
  A driver that dies within its first minute is noticed up to a minute later than before.
- The cleaner fix the entry names, `lym loom start` taking the driver lock before it writes the status and handing it to the driver, was not taken: it reorders the bootstrap that `lym loom step` shares, for a gap the two smaller fixes close.

## Tests

- `TestRunNotice_Conditions` gains a child running with history 0 and no lock held yet, read inside the grace, which sends no notice, and a machine sleep that does not count toward the grace.
  The existing dead-driver rows, `TestRunNotice_OncePerEpisode` and `TestRunNotice_DeliveryIsRetriedOnProbeTicksThenDropped` now move the clock past the grace first.
- `TestChildDriverLockHeld` gains a held loom bootstrap lock reading alive.

# shell-edit guard refuses sed -i and perl -pi after a closed heredoc

The shell-edit row's in-place edit match now reads the commands after a heredoc's closing line and still skips the heredoc body.
Before, a command such as

```
cat > .scratch/fix.pl <<'EOF'
s/a/b/;
EOF
f=docs/x.md; perl -pi -e "$(cat .scratch/fix.pl)" $f
```

passed the guard, while `perl -pi` on its own line was refused.

## Cause

`inPlaceEditCommandPattern` reached command position only through `topLevelReachPattern`.
That pattern's run of shell units stops at a heredoc operator and reads only the operator's own line,
so no command after the heredoc's line was ever in command position.

## Change

- `internal/shellguard/rows.go`: `closedHeredocPattern` returns the match for a heredoc operator, the rest of its line, its body lines and its closing line.
  `inPlaceEditAfterClosedHeredocPattern` matches an in-place edit after one or more closed heredocs, at the top level or in a shell `-c` script that starts there.
  The redirect match and every other row match what they matched before.
- `internal/shellguard/doc.go` and the shell-edit row's comment state the new reach, what still passes and what is falsely denied.
- `internal/shellguard/rows_integration_test.go` pins both the denials and the commands let through.
- The Claude settings golden carries the new pattern.

## Design decisions

- grep -E has no backreference.
  For the delimiter words in `heredocDelimiterWords` the closing line is tied to the operator's word, one alternative per word.
- For any other delimiter word, a line that holds a bare word alone, after optional tabs, closes the body.
  Any text opening a later body line with an in-place edit spelling is then denied, prose naming the command included.
- Still passing, and named in the row's comment: an edit after two heredoc operators on one line,
  later in a shell `-c` script after a heredoc closed inside it,
  and after some delimiter words, such as one opening with a digit or a dash.
- The scope is limited to the in-place edit match, as the entry asks.
  A redirect into a source file after a heredoc's line still passes.

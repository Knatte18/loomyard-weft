# Let a gated darn writer ask its parent to rerun a reported failing test before diagnosing

A darn writer whose verify gate has a cold fixer was told to run no `lym gate test` at all.
A task that starts from a test failure seen on an older base therefore could not check whether the failure still reproduces,
and the writer spent its session tracing a failure that the current base no longer has (issue #119).

## What changes

- `contracts/stencils/darn/darn-fragment-make-change-gated.md`: Step 4's item 1 now opens with a reproduce check.
  When the task starts from a reported test failure, before diagnosing it or editing,
  the writer sends `lym creel post --parent --expect-reply "<text>"` and ends its turn to wait.
  The text names the test exactly and its tier, and asks the parent to run that test once on the writer's base through `lym gate test`.
  A pass whose report shows the named test ran means the failure no longer reproduces,
  and the writer treats the entry as one that landed work overtook, which Step 3 already settles.
  A report that does not show the test ran, because it was skipped for another tier or matched no test, leaves the writer to diagnose as usual.
  Item 3 keeps "Run no `lym gate test` yourself."
  The subagent rule is unchanged: subagents still run no gate.
- `internal/darnengine` and `contracts/stencils`: the doc comments name the writer's request to its parent for the one run.
- Tests: the wiring test and `TestDarnSpec` keep the item-3 line the fragment carries.
  Neither pins the reproduce instruction's prose.

## Design decisions

- The writer asks its parent for the run rather than running the test itself.
  `PATTERN-test-speed` forbids a stencil to name a gate scope form, test command or target list,
  and a package target with `-- -run` is both, and assumes a Go hub.
  A gated writer always has a parent: the fixer is on only for a non-empty pair slug.
- The request names the test exactly and its tier,
  because a run with no tier, or an unanchored name, can skip the test or match another and still pass.
- Only the gated fragment changes.
  The ungated writer already runs the gate itself.
- A pass routes through Step 3's existing outdated-entry path, so the parent decides what the task becomes, and the prompt adds no new stop mechanism.

# Landing notice survives a late request, a down dobby and an absent orch

`landing-watch` left three known limits on the landing notice dobby sends when a task with `notify_on_land` lands.
This change closes all three.

## Behavior

- **A request set after the run landed is answered at once.**
  `lym board upsert` that sets `notify_on_land` on a done entry stores it and returns a notice saying the run already landed, and that the parent's dobby sends the line at its next tick, or only clears the field under `land_notice: off`.
  An upsert that does not touch the field returns no such notice.
  The dobby then sends the line, since the board write wakes its watch.
  A bare `{"slug":…,"notify_on_land":true}` on a slug the board no longer holds is refused, naming `lym batten status <slug>`, instead of filing a new note.
- **A landing dobby missed is still noticed.**
  Board prune keeps a done entry while it carries `notify_on_land`, so the request outlives Land's prune.
  Each tick, dobby takes up every done entry whose parent is its worktree, that this machine owns, and that carries the field with no memory of its own.
  It sends `[dobby notice] <slug>: landed as <commit>` when the run is still listed past Land, and `landed, commit unknown` otherwise.
  A done entry is read as landed whatever set its status.
  This covers a landing made while dobby was down, a fresh state record, and a request raised after the last tick that saw the run ahead of Land.
  A dobby with no clear seam takes up no done entry.
- **A line the orch cannot take waits.**
  Creel now accepts a post to an orch's fixed name of this hub, `<shortname>:orch` or `<shortname>:<slug>:orch`, whether or not a strand of that name is listed.
  The mail stays unread in the pool and is delivered once the orch's strand is back.
  The removed-holder sweep leaves unread mail from a program to such an orch alone, so it waits however long the strand is down.
  On the dobby side, a decided line is kept in the state record as owed and posted at every tick until a post succeeds.
  The old three-attempt cap is gone.
  An owed line survives the run's listing ending, a restart and a re-exec.
- Once the line goes out, dobby clears the entry's `notify_on_land`.
  When no line is owed, as under `land_notice: off`, dobby clears it at once.
  Either way the next prune can drop the landed entry.

## Design decisions

- **The board holds the request across the landing.**
  The decision record asks for "board done state, not only its own state record".
  Land prunes every done entry, so the request was lost with the entry.
  Keeping a flagged done entry until dobby clears it makes the board the durable record, and dobby needs no history of what it saw.
- **One memory, two sources.**
  `LandNoticeState` gains `Line` (the owed notice) and `ClearOwed`, and loses `Attempts`.
  A run seen ahead of Land is decided at Land as before, counting a request read that tick as well as the remembered one.
  A done entry with no memory is decided by the new board step.
  A slug with a memory is never taken up by the board step, so a run gets one line, not two.
- **`off` now clears the request.**
  Before, `off` left the request on an entry that Land then pruned anyway.
  Now prune keeps flagged done entries, so leaving the field would keep the entry on the board forever.
  The `OffSendsNothingAndClearsTheRequest` row pins the new behavior.
- **Creel's rule is narrow.**
  Only this hub's plain orch names pass when unlisted: an orch thread (`orch-N`), another hub's shortname and any other role are still refused as unknown receivers.
  The orch name comes from `orchroute.StrandOf`, which already answers the fixed name when reed no longer holds the strand.
  A prime orch that was never recorded still posts nothing; dobby keeps that line owed and retries it.
- **Only a program's mail waits through the sweep.**
  A program has no mailbox to take a returned message, so the sweep would journal it undelivered; mail from a strand or an EXTERNAL sender to a removed orch, and program mail a strand forwarded to it, still returns as before.
- `battencli.DobbyTasks` now reads the parent worktree and the owner of every entry carrying `notify_on_land`, so a done entry reaches only its parent's dobby, on the machine that owns it.
  An unreadable parent or owner of such an entry is logged once per episode and leaves it unread, and fails the read only for a released task.
  `boardengine` exports `StatusDone` and `IsDoneStatus` for the dobby and CLI checks.

## Tests

- `internal/dobbyengine/landnotice_test.go`, tier 0: rows cover done entries with and without a listed run, under `off`, under another worktree and owned by another machine, a request raised as the run lands (one line), owed lines posted until they succeed, after the run leaves the listing and through a rebuilt daemon, a failed clear retried with no second post, and a failed mode read deciding nothing.
- `internal/dobbyengine/landnotice_creel_test.go`, tier 0: the end-to-end demonstration, described below.
- `internal/creelengine/verbs_test.go`, tier 0: a post and a forward to an unlisted orch of the hub, in both name forms, are stored and read by the strand once it is listed; another hub's orch, an orch thread and a mistyped slug are still refused.
- `internal/creelengine/deliver_test.go`, tier 0: unread program mail to an unlisted hub orch outlives the sweeps and is read once the strand is listed.
- `internal/boardengine/board_test.go`, tier 0: prune keeps a flagged done entry and drops it once cleared.
- `internal/boardcli` `TestCLI`, tier 1: the upsert notice on a done entry and none on a title-only upsert, prune keeping it, and the refusal on a pruned slug.
- `internal/battencli/dobbyreading_test.go`, tier 0: a done entry carrying the field gets its parent and owner read, and an unreadable parent leaves it unread without failing the other tasks.

## End to end

`TestLandNotice_ReachesAnOrchStrandListedAfterTheLanding` is the end-to-end demonstration.
It runs a dobby daemon whose notice seam posts through a real creel store, scheduler and sweep, signed as a program to the prime orch's fixed name, over creel's fake delivery.
With the orch strand unlisted, it ticks the landing of a done entry, runs the sweeps past the point where a removed holder's mail would return, then lists the orch strand and asserts the strand reads `[dobby notice] task: landed as 0123456789ab` once and that the entry's request was cleared.
No hand run against a live orch was made.

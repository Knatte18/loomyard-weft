### [BLOCKING] Restore the path guard on rendered output paths

**Location:** internal/boardengine/render.go:49

**Issue:** `fsx.AtomicWrite` ran `fsx.PathGuard` on every `relPath` (`internal/fsx/fsx.go:79-84`).
It was the only check on the output names that come from config: `Outputs.Readme` from `board.yaml`'s `readme` or `LYM_README` (`internal/boardengine/template.yaml:1`), and `design_prefix`, which `checkDesignPrefix` checks only against the `decision-` clash (`internal/boardengine/config.go:205-213`).
With `os.WriteFile(filepath.Join(boardPath, relPath), …)` a value such as `../outside.md` now writes and truncates a file outside the board directory.
The manifest then records that name, and a later render's cleanup (`render.go:54-60`) removes `filepath.Join(boardPath, name)`, deleting the outside file.
Config is a trust boundary, the fix needs no change to the write mode, and the in-place goal is unaffected by keeping the guard.
Found by the code-correctness lens and the assistant independently.

### [MEDIUM] Restore parent-directory creation for nested outputs

**Location:** internal/boardengine/render.go:49

**Issue:** `fsx.AtomicWriteBytes` created the output's parent directory (`internal/fsx/fsx.go:53`).
The template documents `readme` as relative to the board dir and sets no basename-only rule, so a value like `wiki/Home.md` was valid and its directory was created on the first render.
Now `os.WriteFile` returns ENOENT, and `boardCriticalSection` (`internal/boardengine/board.go:180-194`) reports a render error on every write after `store.Save()`, and skips the sync spawn.
No test at the review base uses a nested output, so this regression passed the gate.

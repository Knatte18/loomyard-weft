### [MEDIUM] Replies to the Slack relay still answer a silent ok

**Location:** internal/creelengine/verbs.go#Store.Reply

**Issue:** The relay check lives in `Store.post`.
`lym creel post --reply <id>` sends `VerbReply`, and `Store.Reply` appends the reply to `original.From` through `appendPostedLocked` (verbs.go:400) without asking the bridge.
Operator Slack text reaches an orch as mail from `ly:SLACK`, so a reply to it is the commonest post to the relay.
An orch whose button went off, or one replying while the relay is down, still gets the silent ok the board entry set out to end.

### [MEDIUM] The orch role file describes the old, silent drop

**Location:** contracts/orchrole/role-slack.md:7

**Issue:** The line reads "While your button is off you have no channel, and mail you post to `<shortname>:SLACK` is dropped."
After the diff the post is refused with a way forward, and a post while the relay is down warns.
The orch reads this file as its instructions on Slack, so it is told the behaviour the diff removed.

### [MEDIUM] Added behaviours with no test row

**Location:** internal/creelengine/machinemail_test.go#TestStore_PostToTheSlackRelay

**Issue:** `slackRelayCheck` exempts only `KindProgram`, so EXTERNAL reaches the bridge, as the summary and `creelengine/doc.go` state; no row posts as EXTERNAL.
The check moved ahead of `interruptBeforePost` so a refused post stops no turn; no row posts with `Interrupt`.
The `receiver != relay` gate keeps a strand receiver's liveness; every row posts to `slack`, and the existing liveness rows run without a bridge.
Breaking any of the three leaves every test green.

### [LOW] Bridge read errors refuse the post with no way forward

**Location:** internal/creelcli/slackbridge.go#slackBridge.RelayPostReady

**Issue:** An error from `b.geometry()`, from `b.beams()` inside `hasButton` for a beam orch, from `ForwardingOn` or from `RelayLive` returns bare through `slackRelayCheck`, and the post is not stored.
Before the diff such a post was stored, and the relay tolerates an unreadable beam listing.
Each of the bridge's own refusals names a way forward; these do not.

### [LOW] The down-relay answer substitutes for the entry's delivered false form

**Location:** internal/creelengine/verbs.go#Store.post

**Issue:** The entry's Idea names two forms: a refusal, or ok with `delivered: false` and the reason.
The diff reuses `receiver_live: false` and puts the reason on stderr only.
The sender is told, which is the entry's aim, but the form departs from the entry's text, and the record holds no added entry for it, so the parent settles it.

### [LOW] The summary misclassifies the turn hook

**Location:** _lym/landing/summary.md:19

**Issue:** `slackcli/hook.go` posts through `c.orchClient()`, a strand client of the orch strand (hook.go:208-217), not as a program.
`slackRelayCheck` skips only program senders, so the hook's post asks the bridge, contrary to the summary's claim.

### [MEDIUM] A reply to Slack mail bypasses the relay check

**Location:** internal/creelengine/verbs.go#Store.Reply

**Issue:** The relay delivers operator Slack text as mail from `<shortname>:SLACK` (`internal/slackengine/inbound.go:765`).
`lym creel post --reply <id>` answers it through `Store.Reply` (`verbs.go:350`), which appends a reply to `original.From` with no call to `slackRelayCheck`.
The relay takes that reply like any orch mail.
It drops the reply when the button is off (`outbound.go:197-200`), and while the relay is down the sender hears nothing.
That is the silent `ok` the board entry describes, reached through a post command whose receiver is SLACK.

### [MEDIUM] New relay-check behaviours have no test row

**Location:** internal/creelengine/machinemail_test.go#TestStore_PostToTheSlackRelay

**Issue:** Every row of the new engine test posts to `slack`.
If the `receiver != relay` guard (`verbs.go:226-229`) were dropped, every local post in a daemon with the bridge would take the relay's liveness or refusal.
No test would fail, because the existing tests that set a bridge and post locally assert neither liveness nor a refusal.
The engine skips the check only for `KindProgram`.
No row pins that EXTERNAL is asked, and no bridge row reaches a read failure.
The assistant rated this BLOCKING through `PATTERN-test-speed`.
That entry governs tiers, redundancy and test mechanics and does not require these rows, so the rubric's test-economy bullet sets the severity, MEDIUM.

### [LOW] A bridge read failure refuses the post without a way forward

**Location:** internal/creelcli/slackbridge.go#slackBridge.RelayPostReady

**Issue:** Before the diff, these posts were stored.
Now a failed read of the geometry, the beam listing, the forwarding file or the relay lock refuses the post with the raw error.
The error does not say that nothing was stored and gives no next step, unlike every other refusal the function returns.

### [LOW] The down-relay answer substitutes for the requested field

**Location:** internal/creelengine/verbs.go#relayDownWarning

**Issue:** The board entry offers two forms: a refusal naming `lym slack start`, or an ok answer with `delivered: false` and the reason.
The diff stores the post and answers `receiver_live: false`.
The reason appears only on the stderr `creel: warning:` line (`cli.go:455`), and the JSON envelope carries no reason (`cli.go:466-473`).

This meets the entry's intent, but no added entry records the substitution, so it goes to the parent.

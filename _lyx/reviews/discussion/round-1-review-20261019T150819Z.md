### [MEDIUM] D2 drops a commit empty from the start, which today's code refuses

**Location:** decision-record.md D2 and Constraints.
**Issue:** I checked with a real repo on git 2.53.
A plain `cherry-pick` of a `commit --allow-empty` commit stops with CHERRY_PICK_HEAD set, `diff --cached --quiet` exits 0, and `cherry-pick --skip` succeeds.
D2's stopped-empty test therefore matches it.
Today's `cherry-pick --empty=drop` on the same commit exits 1 with the pick in progress, because `--empty` applies only to commits that become empty.
So `dropSeedCommits` takes its replay-failure path today, and under D2 it would drop the commit silently on every version.
lyx makes such commits (`gitrepo.CommitEmpty`, used by `commitEmptySnapshot`).
The bound "drops no change" holds for content, but the commit and its trailers are lost, and the Constraint's "same pick result" is false for this case.
The focus question on git 2.43 holds otherwise.
The sequencer's empty stop for a single pick leaves CHERRY_PICK_HEAD set, `--skip` exists since 2.23, and unstaged changes kept by `reset --keep` survive the skip.

### [MEDIUM] D3 promises session-id order that tmux 3.4 does not give

**Location:** decision-record.md D3 and the session-row acceptance criterion.
**Issue:** D3's rationale says `S:` has no sort option in 3.4, and the board entry (#740, #748) records that 3.4 walks sessions in name order.
The second loop has no sort argument, so on the floor version it draws the others by name.
`bar.go:62`'s session-id claim describes the 3.6 shape.
The focus premise holds: tmux 3.4's `S:` takes one format and has no sort option.
A `#{client_session}` comparison inside the loop does give the lit and unlit styles, since the loop's per-session format keeps the client.

### [MEDIUM] The prime marker misses a live session left by an older binary

**Location:** decision-record.md D3 and the older-binary criterion.
**Issue:** `ensureSessionLocked` (`internal/reedengine/lifecycle.go:763-773`) returns early on a usable session without booting.
Attach (`internal/reedengine/attach.go:81-97`) is where reed re-asserts display options for sessions an older lyx spawned, and it re-pins the new `status-format[1]` there.
After a deploy, the new row is therefore live while the prime stays unmarked and is not drawn first until the server restarts.

### [MEDIUM] D6's marker does not identify the receiver's probe

**Location:** decision-record.md D6 Fix.
**Issue:** `Delivery.Strands` is also called by `sweepOnce` (`internal/creelengine/sweep.go:114`), by other receivers' workers, and by store verbs through `readStrands` (`verbs.go`).
The fake's `Strands()` takes no receiver.
In `HoldMutes…`, `tick(31 * time.Minute)` fires the sweep too.

The diagnosis itself follows from the code.

The fix targets the cause, the test's synchronization, but the marker needs to be specific to the receiver.

### [MEDIUM] Caching of an admitted unparseable version line is undefined

**Location:** decision-record.md D4.
**Issue:** D4 caches a parsed result and retries a probe that cannot run, and an admitted unparseable line is neither.
Hook-driven reed tests answer an unscripted verb with an empty line (`faketmux_test.go`), so routing the probe through the hook gives exactly that case.
Uncached, it adds a `-V` call and a Warn before every command in every such test.
In production, a vendor-build tmux in the watchdog daemon would get a Warn per command.

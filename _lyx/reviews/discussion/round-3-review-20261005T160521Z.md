### [MEDIUM] llm loss bounded for smoke files only

**Location:** `decision-record.md` D6 Bound; Acceptance criteria, retag bullet.
**Issue:** D6 says a file that spawns an LLM session moves to `llm` "whichever tag it carried".
The Bound states the loss only for files moved from `smoke` ("leave every automatic run, including any plan verify that ran `-tags smoke`").
A file moved from `integration` to `llm` also leaves `cardGateCommand`'s `go test -tags integration` run and every `-tags integration` verify.
The reader cannot tell that this loss is intended.
The retag acceptance bullet covers only files retagged "into `integration` or `tmux`", so the `integration` to `llm` route has no criterion.
The `llm` wording is otherwise consistent: no sentence promises a gate runs an `llm` file, and `go vet -tags llm` is the stated compile check.
**Fix:** In the Bound, say that files moved to `llm` from either tag leave every automatic run, which is intended because the tier costs tokens.
In the acceptance bullet, cover files retagged into `llm` too.

### [MEDIUM] Acceptance never runs the tmux tier

**Location:** `decision-record.md` Acceptance criteria, last bullet.
**Issue:** D6 names the plan verify as what keeps tmux-tier tests run, through `-tags tmux`.
The closing bullet lists `go build`, `go vet -tags integration,tmux,llm`, `go test ./...` and `go test -tags integration ./...`, and no `-tags tmux` run.
The tier's own tests can break unnoticed.
The Bound's claim that the plan verify runs `-tags tmux` is within this task's reach, since the plan writes its own verify.
Only `cardGateCommand` is out of scope, and the Bound states that correctly.
**Fix:** Add `go test -tags tmux ./...` to the closing bullet.

### [LOW] "Cannot classify" is undefined

**Location:** `decision-record.md` D2, spawning-test bullet.
**Issue:** The scan follows same-package helpers and matches `os/exec`, `lyxbin`, `tmuxkit` or another testkit spawn helper.
The rule "a test it cannot classify counts as spawning" does not say what unclassifiable is.
Read literally, any call into another package is unclassifiable, which would move most tests into "no coverage".
The direction of the error is decided correctly: it lands in "no coverage", never "redundant".
**Fix:** State that unclassifiable means a call the scan cannot resolve to source, such as a function value or an interface method.
Calls into production packages are not followed, since their blocks are covered in-process, and testkit and hubforge helpers are classified by the same scan.

### [LOW] Retired-ID acceptance criterion contradicts the record

**Location:** `decision-record.md` Acceptance criteria, PATTERN bullet.
**Issue:** "no file references a retired entry ID" is false the moment it is checked: this record, the support log and the board entry name the retired IDs.
D8 scopes the rewrite to code comments, stencils, specs and docs.
**Fix:** Scope the criterion to the same set as D8 and exempt the discussion artifacts.

### [BLOCKING] Strict status read before every spawn refuses a poisoned status file (died-driver smoke test)

**Location:** `internal/loomcli/start.go:312` (call) and `internal/loomcli/start.go:166` (`currentProducer`)
**Issue:** The diff makes `runDriverSpawnAndWait` call `c.currentProducer()` before `refuseOverUnfinishedMerge` whenever `mustSpawn || parkedLive`.
`currentProducer` reads the status file with `state.ReadJSONStrict`, and on any error `runDriverSpawnAndWait` releases the bootstrap lock and writes `output.Err`, a refusal envelope.
`TestSmokeBootstrapLifecycle/died_driver_proceeds_to_the_success_envelope_and_logs_why` poisons the committed status file with an unknown field and expects `lyx loom start` to reach the success envelope, because the bootstrap's steps use "only the lenient read paths" and "only the spawned CHILD's strict read gate ever sees the failure".
The new read breaks that contract: the publish log shows `{"error":"state: decode failed: json: unknown field \"__smoke_unknown_field__\"","ok":false}`, and no `driver.log` is ever written because no driver is spawned.
The producer is needed only when the probe reports a parked `merge-in`, which is rare; the read runs on every spawn, including a pair with no merge at all.
Card 6 says `runDriverSpawnAndWait` "reads it right before its probe", so the plan prescribes the eager read; the plan is not the subject, but the diff still has to keep the bootstrap contract that the smoke test pins.
**Fix:** Do not let a status read failure refuse a spawn.
Either read the producer only after the probe reports `MidMergeParked` with verb `merge-in` (for example by passing a closure instead of a string into `refuseOverUnfinishedMerge`), or keep the signature and have `runDriverSpawnAndWait` treat a read error as "no landing producer" (pass `""`, log at warn), so the ordinary merge refusal stands and the driver's own read gate reports the decode failure.
Add a non-tmux row to `TestRunDriverSpawnAndWait_MidMerge_CleanPairProceeds` with an undecodable status file and a clean pair, asserting the driver is spawned.

### [BLOCKING] Malformed status file is refused at bootstrap instead of deferring to the driver's read gate (malformed-status smoke test)

**Location:** `internal/loomcli/start.go:166`
**Issue:** The same strict read fails on a truncated status file with `state: decode failed: unexpected EOF`.
`TestSmokeBootstrapLifecycle/malformed_status_proceeds_to_the_success_envelope_and_logs_why` guards the earlier fix that made `loomshed.Seed` tolerate this file so that "the spawned driver's own Shed.Run step-1 read gate diagnoses the decode failure in the driver log".
The new `currentProducer` call reintroduces the refusal one step later, and the publish log shows the refusal envelope and a missing `driver.log`.
Lenient `state.ReadJSON` would not help here: it also errors on malformed JSON, so the fix has to be where F1 puts it, not a swap of the reader.
**Fix:** The F1 fix covers this finding; the malformed-file row should sit beside the unknown-field row in the unit test F1 adds.

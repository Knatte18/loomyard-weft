### [LOW] The `loopAgreesWithState` reason for a held run beside busy on background work does not match what the code produces

**Location:** `internal/shuttleengine/waitshadow.go:77`, `internal/shuttleengine/waitshadow_test.go:117`

**Issue:** The comment says a held or done run beside busy on background work arises because "a turn end counted at once, or a plain Stop after a waiting one, leaves the session running tasks the loop no longer waits on".
The done half is real: a waiting turn end counted at once finalizes Done while the session still reads `busy/background`, and the row `done beside busy on background work is expected` pins it.
The held half is not produced:
- `claudeengine.ParseEvents` classifies a `Stop` with outstanding tasks as `EventWaiting`, so a plain `EventStop` carries none.
- `judgeTurnEnd` reads a turn end with no outstanding tasks as `idle-stalled`, `asking` or `idle-done`, never `busy/background`.
- `expiredTurnEnd` no longer returns a held turn end carrying tasks, which was the only source of the pairing before card 22.
- `Wait` calls `endHeldWait` whenever a tick reads new events, so a later waiting turn end moves the loop to `waiting` before the shadow compares.

The `|| busyOnBackground` clause on `loopHeld` therefore allows a pairing no code path reaches.
The card asked for the expired-shell row to be reworded "to a held turn end beside busy background work".
The row now reads `a waiting turn end on transcript-reported shells past the bound beside busy on background work is expected` and expects `busy/background waiting`, which the base mapping (`loopWaiting` reads busy) already allows and the first row of the same table, `a turn start, a waiting turn end, a held turn end and done`, already expects.
So no row exercises the held allowance, and the renamed row pins nothing that row does not.

**Fix:** If a held run beside `busy/background` can occur, add a row that drives it and state the real cause in the comment.
Otherwise drop `|| busyOnBackground` from `loopHeld`, say the allowance covers a done run only, and delete the renamed row, since the first row and the base mapping cover it.

**Intent:**
`cmd/testtiming` gains a redundancy mode, `-redundancy`, beside its timing mode (D1, D2).
Flags: `-out <path>` names the markdown report it writes (default `docs/benchmarks/test-redundancy.md`), `-pkg <pattern>` limits the packages (default `./...`), and `-tags` (card 1) defaults to `integration,tmux` in this mode, every tier but `llm`.

`redundancy.go`, per package with tests under the tags:

- lists its top-level tests (`go test -list '.*'` with the tags);
- builds one coverage binary, `go test -c -cover -covermode=set -coverpkg=<every package of the module>` with the tags and cgo on (`PATTERN-quarry-cgo`), into a temp directory;
- runs it once per top-level test (`-test.run '^Name$'` with `-test.coverprofile` and `-test.v`), in the package directory, recording elapsed, pass/fail/skip and the covered block set parsed from the profile (file, position range; a block counts when its count is non-zero);
- classifies each test: "no coverage" when it covers no block, ran skipped, or the spawn scan marks it; otherwise a candidate when its block set is a subset of the union of the other tests' sets in the package, with the covering tests named in order of overlap;
- marks the removable set: a greedy pass over the candidates, slowest first, that drops one, re-checks each remaining candidate against the tests still kept, and continues.

Wall time is the package's own run of all its tests (one `go test -json` run, as timing mode does), serial time the sum of the per-test elapsed times, and the count the number of top-level tests.
A package whose binary fails to build or whose test fails is reported with that error and the run exits 1 at the end, after writing the report.

`spawnscan.go` decides "spawns a subprocess" statically over the package's `_test.go` sources with `go/parser`: a test spawns when it, or a function it calls that is declared in the package's own test or production sources, references `os/exec`, `lyxbin`, `tmuxkit` (other than `Main`), `gitkit` (other than `HermeticGitEnv`), `hubforge`, or another testkit spawn helper found by the same scan over `internal/testkit/`.
Calls into other production packages are not followed, since their blocks are covered in-process.
A call the scan cannot resolve to source (a function value, an interface method, a method on an unresolved type) counts as spawning, so an error lands in "no coverage", never in "redundant" (D2).

The report has one H2 per package (its short import path) holding a header line with test count, wall time and serial time, then a candidates table (test, covering tests, removable yes/no), then the "no coverage" list with each test's reason (no blocks, skipped, spawns, unclassifiable call).
It is generated by the tool and committed as written (D3);
it links nothing it cannot resolve (`PATTERN-markdown-link-integrity`), and its text uses one sentence per line.
The `go` spawns are a dev tool outside `lyx` commands, so `PATTERN-spawn-observability` does not apply.

Tests are untagged and spawn nothing: `redundancy_test.go` drives the classification on in-memory block sets (subset, mutual pair where the removable set keeps one, slowest-first order, empty set to "no coverage", skip to "no coverage", a spawning test never a candidate) and the profile parser on a canned profile, and renders one package's report section and compares it exactly;
`spawnscan_test.go` parses fixture sources from a temp directory and asserts each rule (direct `exec.Command`, a same-package helper chain, `tmuxkit.Main` alone not spawning, a function-value call counting as spawning, a production-package call not followed).
`main_test.go` gains rows for `-redundancy`'s flag defaults.

`pattern/PATTERN-test-economy.md` gains the reading of the report: a candidate is evidence, not a verdict, since coverage blocks do not see assertions;
a prune finding names the covering test from the report, and only the removable set may be deleted together.
Per-card verify runs the mode on one small package, which no unit test can reach.

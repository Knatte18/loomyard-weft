# Bolt and hub stores: forward-only seeding, pull-first writes, quieter gc

Stencil and spec seeding no longer flips Bolt between two binaries' versions, and lyx's other git writes to Bolt and the hub object stores stay correct and quiet.

Closes #477
Closes #478

## What changes

- A stencil refresh is forward only.
  The stamp line of a seeded file now records the writing binary's revision and commit time beside the body hash.
  `stencilstore` refreshes an untouched, differing copy only when the running binary is newer than the recorded writer, or when the file records no revision.
  Newer is decided by commit ancestry when the code worktree holds both commits, and by strictly later commit time otherwise.
  A file the rule does not find older is left alone with one Info line naming both revisions and `lyx stencil sync` as the override.
  The specs pass follows the same rule.
- Only a clean, stamped, production-channel binary refreshes.
  `buildinfo` gains a production channel, stamped by `tools/deploy` on the route `update-plugins.sh` runs.
  `stencilstore.Mode` gains a third value for an unstamped binary, and the zero value is now that mode.
  A dev, unstamped, modified-tree or revision-less binary seeds absent files only and warns.
  `buildvcs` now reports the commit time and whether the tree is clean.
- Every seed commit names its binary: `lyx: seed <subtree> (<short revision>[-modified], <channel>, <executable path>)`.
  `lyx stencil sync` commits under its own prefix, `lyx: sync <subtree>`, with the same label.
- The root pre-run classifies first and fetches only when a write is due.
  With a write due, it drops seed commits ahead of upstream, fast-forwards Bolt, classifies again and writes.
  A transport failure, or a Bolt that diverges with non-seed commits, skips the writes with one Warn naming the way forward.
- `hubreconcile`'s hub-wide config write and `lyx fabric reconcile`'s hub-config heal run the same fetch, drop and fast-forward first.
  `hubreconcile` leaves the build stamp absent when its push fails, so the next start verb reruns the walk.
- `lyx fabric reconcile` now exits non-zero, with the envelope and detail fields kept, when the hub config or the warp binding fails to commit or push.
  The long help no longer says a push failure leaves the exit code unchanged.
- Bolt's push, on a `pull --rebase` that fails, drops seed commits from the ahead set and retries the rebase and push once.
  The dropped content is regenerated by the next refreshing binary's pre-run.
- Hub store gc at pair removal is skipped, with the key writes kept, while another pair's reed session is live.
  The skip logs at Info with the sessions found; a probe error counts as in flight and logs at Warn.
  `fabric remove` and the batten teardown both pass the real probe.
- The same gc passes `gc.pruneExpire=1.day.ago`, so unreachable loose objects older than a day are pruned and the gc stops repacking at every teardown.

## Design decisions to review

- The drop primitive lives in `fabricengine/destroy.go` behind the destruction chokepoint: containment, ownership, dirtiness and never force, in that order, with the mutation record appended.
  It resets Bolt to upstream through `ResetKeep` and replays the remaining ahead commits; on a replay conflict it restores the original tip and refuses.
- A commit is a seed commit only if its subject is `lyx: seed <subtree>` plus the D3 label and every path it touches is under the stencils or specs subtree.
  Seed commits made by a pre-change binary carry no label and are never dropped, so a conflict on one fails the push as before.
  `lyx: sync` commits and hub-wide config commits never match.
- `stencilstore` still runs no git; the ordering answer comes through its `Source`, which `fabricengine.StencilSource` implements with an object-presence check followed by `IsAncestor`.
- The gc skip is an injected in-flight probe on `housekeepStores`, so the skip is testable at the integration tier.
  The prime's own sessions and the removed pair's sessions never count; no tmux server on the socket means no sessions.
- The one-day prune expiry lets gc delete unreachable loose objects between one day and two weeks old, which git's default kept.
  `pattern/PATTERN-hub-store-gc.md` records the new expiry and the skip.
- Docs updated with the code: the `doc.go` of each touched package, the stencil row of `docs/overview.md`, `pattern/PATTERN-hub-store-gc.md` and `pattern/PATTERN-leaf-packages.md`.

## Known limits

- A pre-change binary still in use strips the recorded revision when it overwrites a stencil, and the new binary refreshes again; the flip ends when no pre-change production binary runs against the hub.
- Where the commit-time fallback applies, a production build committed on a machine with a skewed clock can refresh a stencil backwards once.
- A hub-wide config commit whose push conflicts is not dropped; it holds the stamp absent and blocks due pre-run writes until the operator resolves `git pull --rebase` in the board dir.
- A hub that is never quiet at a removal, or whose probe fails at every removal, is not gc'd by lyx until a quiet removal; the manual `git gc` stays the override.

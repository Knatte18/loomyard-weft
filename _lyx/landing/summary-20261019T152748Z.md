# Fork git-mutation guard classifies by the git subcommand

Burler's fork audit hard-fails a review round when a fork runs a state-mutating git command.
Its regex, `mutatingGitPattern`, matched a mutating verb anywhere among git's later words, so a read-only lookup such as `git help -m cherry-pick 2>/dev/null | col -b | grep -n -A14 "^ *--empty"` was refused, and so were `git log --grep merge` and `git show tag`.
That refusal halted a run after its Write and Bouncer rows had finished, and the review round was discarded (issues #750 and #751).

`commandRunsMutatingGit` in `internal/burlerengine/cluster.go` replaces the regex.
It splits the command into segments at `;`, `&`, `|` and newlines with a quote-aware tokenizer that honours backslash escapes, comments and backslash-newline continuations.
A segment counts only when its first word is git, bare or path-prefixed, and only its subcommand decides: the first non-option word after git's global options, skipping the value word of `-C`, `-c`, `--git-dir`, `--work-tree`, `--namespace`, `--config-env` and `--attr-source`.
A segment passes when `-h` or `--help` is among git's global options or is the first word after the subcommand, because it then only prints usage or a man page.
The set of mutating subcommands is unchanged.

## Design decisions

- A newline now separates commands the way `;` does, so a mutating git call on a later line of a multi-line command is refused; the old pattern anchored only at the start of the string and missed it.
- The `-h`/`--help` escape covers only those literal words, and only among git's global options or directly after the subcommand; they make every git builtin print usage and exit before it changes anything.
- Commands in a subshell `(...)` or behind an environment assignment stay unclassified, as they were.

## Tests

`TestMutatingGitPattern` is renamed `TestCommandRunsMutatingGit` and now runs in parallel.
It has new rows for `git help` on a mutating verb (the issue's command verbatim), `git --help commit`, `git commit --help`, `git rebase -h`, a mutating verb as a `log` or `show` argument, `-C` whose value names a mutating verb, `-c key=value` before `commit`, and a commit on a later line.
The fork-audit paragraph in `internal/burlerengine/doc.go` now states the subcommand rule.
